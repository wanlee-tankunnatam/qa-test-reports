takra-rerun

ส่วนสิ่งที่พบผลต่อโหลดเทส
backend (Go, chi)ประมาณ 170 route ในไฟล์ router เดียว รวมทุกไฟล์ประมาณ 374 จุดลงทะเบียน · โหมดเดสก์ท็อปฟังที่ loopback 8080 · มีโหมด cloud ฟัง :8080 ทุก interface · มี /healthz · ใช้ OIDC login (/auth/login, /auth/callback)ไม่ใช่เป้าหมายโหลดหลัก เพราะเป็นของเครื่องเดียว ใช้ทดสอบเป็น 'ประสิทธิภาพบนเครื่อง' (CPU/RAM/ffmpeg) แทน ยกเว้นถ้ามีโหมด cloud ที่มีผู้ใช้หลายคนจริง ต้องถามทีม
central (Go, chi, pgx)50 route · /health, /me, /entitlement, /locks (+/locks/{account}/heartbeat), /accounts, /sessions/metrics (+ summary/daily), /llm/reply, /llm/models, /llm/usage, /presign-upload, /presign-download, /usage, /overview, /workspaces/{id}/sessionsเป็นเป้าหมายโหลดหลักของ Rerun ทุกเครื่องที่ติดตั้งแอปเรียกเข้ามา
กลุ่มที่ต้องยิง (central)locks/heartbeat (หลายเครื่องส่งถี่ ๆ ระหว่างไลฟ์), sessions/metrics (ส่งขึ้น), me/entitlement (ตอนเปิดแอป), presign-* (ไฟล์)scenario หลักของ central ใหม่: เครื่องจำลองหลายเครื่อง × heartbeat + metrics + entitlement
ต้อง mock / ห้ามยิงจริง/llm/reply (เรียก LLM เสียเงิน), presign-upload/download (ไป R2/S3 จริง ต้องใช้ bucket ทดสอบหรือข้าม)ใช้ helper กัน + ตรวจ base URL
RealtimeSSE: /sessions/{id}/events, /auto/events (เป็น text/event-stream) ไม่พบ WebSocketทดสอบจำนวน SSE ค้างได้ แต่ฝั่ง backend ของเครื่องเดียว จึงเป็นเรื่องประสิทธิภาพบนเครื่อง
Mock ที่มีในโค้ดSESSION_PROVIDER=sara-mock และ FAKE_FFMPEG=1 ตรงกับที่ระบุไว้ใน ruleยืนยันแล้วว่ามีจริง ใช้ได้
Rate limit / quotaไม่พบ rate limit ทั่วไปใน central มี quota ตามแพ็กเกจ (EnforceQuota: จำนวนบัญชี, session พร้อมกัน) · มี Retry-After ในโค้ด centralต้องยืนยันว่า central มีตัวจำกัดอัตราหรือไม่ตอนรัน smoke
Authbackend: JWT → entitlement → quota (chi middleware) · central: JWT และ header ลับของบริการภายใน (เส้นภายใน)ต้องมีโทเคน UAT ของ Hub · ห้ามใช้ header ลับของบริการภายใน จริง
