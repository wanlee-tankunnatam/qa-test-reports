ai.16Stress + Spike
  • ตั้ง abort threshold ในสคริปต์ (เช่น error เกิน 20%) ให้หยุดเองก่อนระบบล่มจริง
  • ไล่เพิ่มโหลดทีละ 25% จนเกิน 3–5 เท่าของปกติ หรือจนเกณฑ์ไม่ผ่าน
  • จดจุดที่ latency/error เริ่มพุ่ง = เพดานระบบ
  • Spike: กระโดดเป็น 5 เท่าทันที 2 นาที แล้วลดกลับ
  • ดูว่าระบบกลับมาปกติเองโดยไม่ต้อง restart ไหม
  • ให้ DEV เฝ้าฝั่งเซิร์ฟเวอร์ระหว่างรัน
  • รันนอกเวลางานที่จองไว้ (G.7) เพราะ uat กับ prod ใช้ node ร่วมกัน stress บน uat อาจกระทบ prod
  • uat เป็น single-replica จึงได้เพดานต่อ pod ส่วน prod มี HPA ต้องประมาณจำนวน replica เอง ไม่เทียบตรงๆ
  • จด build/commit และ CPU limit ของรอบนั้น (เช่น hub ก่อน/หลัง การปรับ CPU limitเป็นคนละเครื่อง)

  • เทียบต้นกับท้ายชั่วโมง: RAM โตเกิน 10% ถือว่าสงสัย memory leak
  • หลังหยุดโหลด ตรวจว่าคิวกลับเป็น 0 และ connection ถูกคืน
