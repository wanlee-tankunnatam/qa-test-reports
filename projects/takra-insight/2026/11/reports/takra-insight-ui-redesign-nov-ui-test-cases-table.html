🧩 Epic TI-713 · Priority: P0 · E2E · ประเภท: Happy Path (flow ปกติ) · Journey วิเคราะห์คลิป TikTok / Facebook — วางลิงก์ถึงรายงาน · ลิงก์มีปัญหา
📌 หมายเหตุ: FAIL ถ้ามีขั้นค้าง "กำลังทำ" หลังรายงานเปิด หรือชื่อคลิปไม่ตรงกันระหว่างรายงาน คลิปล่าสุด และวิเคราะห์ย้อนหลัง · ตัวเลขเวลาขึ้นกับความยาวคลิปจริง (≈ ความยาว + 5 ถึง + 30 วินาที)

Precondition

  • แอปล็อกอิน TikTok ไว้แล้ว
  • ให้ความยินยอมอ่านสีหน้าและฟังเสียงแล้ว
  • ไม่มีไลฟ์กำลังบันทึกอยู่ในแอป

Test Data

  • บัญชีที่ใช้ (UAT): qa.owner@realfactory.co.th · บทบาท "เจ้าของ"
  • ลิงก์คลิป TikTok สาธารณะของบัญชีทดสอบ QA ยาวประมาณ 30 วินาที เห็นหน้าคนพูด และมีคนพูด 2 เสียงขึ้นไป

Test Steps

  1. เปิดแอป TAKRA Insight (UAT) แล้วเข้าสู่ระบบด้วยบัญชีเจ้าของ ไปที่เมนู "คลิป" แล้วกดปุ่ม "?" ท้ายช่อง "วางลิงก์คลิป" อ่านรูปแบบลิงก์ในแผงที่เปิด แล้วปิดแผง
  2. วางลิงก์คลิป TikTok แล้วกด "เปิดคลิป" สังเกตข้อมูลคลิป ปุ่ม และบรรทัดเวลาใต้ปุ่มในหน้าตรวจคลิป
  3. กด "เริ่มวิเคราะห์" แล้วดูหน้า "วิเคราะห์คลิป" จนเสร็จ สังเกตบรรทัดเวลาและสถานะของ 3 ขั้นตอน
  4. เมื่อรายงานเปิดเอง สังเกตหัวรายงานและ "สถิติของคลิป" ในส่วน "ภาพรวม"
  5. กดแท็บ "บทพูด" แล้วอ่านหัวการ์ดและบรรทัดข้อมูลเหนือช่องค้นหา
  6. ไปที่เมนู "คลิป" สังเกตแถวบนสุดของ "คลิปที่วิเคราะห์ล่าสุด" แล้วกด "ดูทั้งหมด"
  7. ในหน้า "วิเคราะห์ย้อนหลัง" แท็บ "คลิป" กดแถวคลิปนี้ แล้วกด "วิเคราะห์ย้อนหลัง" ที่แถบเส้นทางด้านบน สังเกตแท็บที่ถูกเลือก

Expected Result

  • แผงลิงก์: หัวแผง "ลิงก์คลิปที่ใช้ได้" มีรูปแบบลิงก์ TikTok (tiktok.com/@…/video/… · vt.tiktok.com/…) และ Facebook ปิดแผงแล้วใช้ช่องต่อได้
  • ตรวจคลิป: เห็นปก "โดย @ชื่อช่อง" ความยาว ยอดวิว/ไลก์/คอมเมนต์ มีแค่ปุ่ม "เริ่มวิเคราะห์" (ไม่มีปุ่มอัปโหลด) และ "ใช้เวลาประมาณ 35–60 วินาที" ก่อนกดเริ่ม
  • ความคืบหน้า: 3 ขั้น "ดึงวิดีโอ" → "ถอดเสียง" → "อ่านคอมเมนต์" เปลี่ยนสถานะเป็นคำ "รอ" / "กำลังทำ" / "เสร็จ" และเวลานับถอยหลัง "เหลืออีกประมาณ …" ไม่ติดลบ แล้วเปิดรายงานเอง
  • รายงาน: หัวรายงานมีคำว่า "TikTok" ข้างไอคอน @ชื่อช่อง ป้าย "วิเคราะห์เสร็จ" และ "สถิติของคลิป" 5 ช่อง "ยอดดู" "ไลก์" "คอมเมนต์" "แชร์" "บันทึก" กำกับ "ณ เวลาวิเคราะห์ …"
  • บทพูด: หัวการ์ด "บทพูดของคลิป" และบรรทัดข้อมูลพูดว่า "คลิปนี้" (เช่น "ระบบได้ยินอย่างน้อย 2 เสียงในคลิปนี้ …") ไม่มีคำว่า "ไลฟ์นี้"
  • คลิปล่าสุด: แถวบนสุดเป็นคลิปนี้ ชื่อเดียวกับหัวรายงาน มีป้าย "คลิป TikTok" และวันที่
  • วิเคราะห์ย้อนหลัง: "ดูทั้งหมด" เปิดหน้า "วิเคราะห์ย้อนหลัง" ที่แท็บ "คลิป" แถวคลิปนี้มีป้าย "คลิป TikTok" ชื่อเดียวกับรายงาน
  • แถบเส้นทาง: ในรายงานเป็น "วิเคราะห์ย้อนหลัง" › ชื่อคลิป กดแล้วกลับมาหน้า "วิเคราะห์ย้อนหลัง" ที่แท็บ "คลิป"

  1. เปิดแอป TAKRA Insight (UAT) แล้วเข้าสู่ระบบด้วยบัญชีเจ้าของ ไปที่เมนู "ไลฟ์" วางลิงก์ไลฟ์ของบัญชีทดสอบในช่อง "เพิ่มไลฟ์ที่จะบันทึก" กด "เปิดดูไลฟ์" แล้วกด "เริ่มติดตาม" → "เริ่มบันทึก" รอให้บันทึกอย่างน้อย 5 นาที

Precondition

📌 หมายเหตุ: ใช้ไลฟ์จริง ทดสอบด้วยมือ — ใช้บัญชีทดสอบของ QA เปิดไลฟ์เอง · FAIL ถ้า "ภาพค้าง" ไม่ขึ้นหลัง 45 วินาที รายการเสียงหายในแถบ "ต้องดู" เป็นสีส้มหรือขึ้น "เงียบสนิทมา 20 วิ" หรือ Telegram ส่งซ้ำ · ถ้าช่อง A ไลฟ์หลุดก่อนครบ 90 วินาที ให้ลดเวลาตัดเน็ตแล้วทำใหม่

Precondition

  • บัญชีเลือกพื้นที่ทำงานไว้แล้ว และพื้นที่ทำงานให้ความยินยอมอ่านอารมณ์จากสีหน้า และฟังเสียงพูดระหว่างไลฟ์ไว้แล้ว
  • บัญชี TikTok ทดสอบของ QA เปิดไลฟ์อยู่ 2 ช่อง (ช่อง A · ช่อง B) คนละเครื่อง มีภาพและเสียงพูดปกติ — QA คุมเน็ตของเครื่องช่อง A และไมค์ของเครื่องช่อง B ได้
  • หน้า "แจ้งเตือน Telegram" ของพื้นที่ทำงานนี้เชื่อมบอททดสอบกับกลุ่ม Telegram ทดสอบของ QA ครบ 3 ขั้น ส่งทดสอบผ่าน และเปิด "ส่งแจ้งเตือนเข้ากลุ่ม" อยู่ (ทำ TC-JRN-C.1 แล้ว)

Test Data

  2. ที่เครื่องออกอากาศช่อง A ตัดเน็ตราว 90 วินาทีโดยไม่กดจบไลฟ์ จับเวลา แล้วดูแถบใต้ภาพของการ์ด A แถบ "ต้องดู" และกลุ่ม Telegram ทดสอบ
  3. ต่อเน็ตเครื่องช่อง A กลับ แล้วดูการ์ด A และแถบ "ต้องดู" ตั้งแต่ภาพขยับอีกครั้งจนครบราว 30 วินาที พร้อมดูกลุ่ม Telegram

  5. ปล่อยให้ช่อง B เงียบต่อจนเกิน 1 นาที แล้วดูข้อความบนการ์ด B และในแถบ "ต้องดู" อีกครั้ง พร้อมนับข้อความ "เสียงไลฟ์หาย" ในกลุ่ม Telegram
  6. เปิดไมค์ช่อง B กลับแล้วพูดต่อ ดูการ์ด B และกลุ่ม Telegram ต่ออีกราว 1 นาที

Expected Result

  • เสียงหายช่วงแรก: การ์ด B และรายการในแถบ "ต้องดู" เป็นสีแดงทั้งคู่ (ไม่ใช่สีส้ม) "เสียงไลฟ์หาย · HH:MM" และ "เงียบสนิทเกิน 20 วิ · ยังไม่กลับมา" ข้อความคงที่ ไม่นับเลข 20, 21, 22… (ถ้าเป็น "ไม่มีสัญญาณเสียงเกิน 25 วิ · ยังไม่กลับมา" ให้จดไว้) · การ์ด A ไม่ได้รับผลกระทบ

  • เสียงกลับมา: ไม่นานหลังพูดต่อ คำว่า "ยังไม่กลับมา" หายจากการ์ด B ป้าย "เสียงไลฟ์หาย" ค้างอีกช่วงหนึ่งแล้วหายเอง · กลุ่มไม่มีข้อความแจ้งว่าเสียงกลับมาแล้ว

📌 หมายเหตุ: FAIL ถ้าตัวเลขบนแท็บไม่ตรงกับหัวรอง หรือแท็บคลิปขึ้น 0 ทั้งที่มีคลิป

Precondition

  • พื้นที่ทำงานปัจจุบันมีไลฟ์ที่วิเคราะห์แล้วอย่างน้อย 3 ไลฟ์ และคลิปที่วิเคราะห์แล้วอย่างน้อย 2 คลิป (TikTok 1 · Facebook 1)
  • ปิดแอปแล้วเปิดใหม่ก่อนเริ่ม และยังไม่เปิดแท็บคลิป เมนู "คลิป" หรือรายงานคลิปในรอบนี้

Test Data

  • บัญชีที่ใช้ (UAT): qa.owner@realfactory.co.th · บทบาท "เจ้าของ"

Test Steps

  1. เปิดแอป TAKRA Insight (UAT) แล้วเข้าสู่ระบบด้วยบัญชีเจ้าของ ไปที่เมนู "วิเคราะห์ย้อนหลัง" แล้วสังเกตตัวเลขหลังคำ "ไลฟ์" และ "คลิป" บนแท็บ
  2. กดแท็บ "คลิป" รอรายการขึ้น แล้วกดกลับแท็บ "ไลฟ์"
  3. พิมพ์คำที่ไม่มีในรายการลงช่องค้นหา แล้วสังเกตตัวเลขบนทั้งสองแท็บอีกครั้ง

Expected Result

  • ตัวเลขบนแท็บ "ไลฟ์" เท่ากับ N ในหัวรอง "N ไลฟ์ที่บันทึกไว้" และตัวเลขบนแท็บ "คลิป" เท่ากับ N ใน "N คลิปที่วิเคราะห์ไว้"
  • ก่อนเปิดแท็บคลิปครั้งแรก แท็บ "คลิป" อาจยังไม่มีตัวเลข (ไม่ขึ้นเลข 0) — หลังเปิดแท็บคลิปแล้วตัวเลขขึ้นและคงอยู่แม้กลับมาแท็บไลฟ์
  • ค้นหาหรือกรองจนรายการว่าง ตัวเลขบนแท็บยังเป็นจำนวนทั้งหมดเท่าเดิม
ที่มา: TI-700 (แท็บพร้อมจำนวน — นับจากรายการที่โหลดแล้ว ไม่โหลดคลิปเพื่อนับอย่างเดียว) · FR149
