Priority: P0 · UI · ประเภท: Negative (สิ่งที่ต้องไม่เกิดระหว่างไลฟ์) · 🧹 Round 1 — เคลียร์ของค้างที่บล็อกความเชื่อมั่น

Test Steps

  1. เปิดเว็บ TAKRA AI แล้วเข้าสู่ระบบด้วยบัญชี UAT → ที่หน้าหลักกด "เปิดห้องไลฟ์" ของห้องที่จะใช้ทดสอบ
  2. เปิด Studio เลือกฉากที่มีสื่อวิดีโอ แล้วตั้งค่าให้คำเตือน/เส้นแดงโหมดวิดีโอขึ้นบนผ้าใบ
  3. จดว่าคำเตือนขึ้นที่ตำแหน่งไหน ข้อความว่าอะไร (แคปหน้าจอไว้)
  4. กดเริ่มไลฟ์ด้วยโหมดส่งตรง แล้วรอให้ขึ้นไลฟ์จริง
  5. กลับมาดูผ้าใบ/แผงตั้งค่าเดิมระหว่างไลฟ์ยังเดินอยู่
  6. หยุดไลฟ์ แล้วรีเฟรชหน้า (F5) ดูอีกครั้ง

Expected Result

  • คำเตือน/เส้นแดงยังอยู่ครบทั้งระหว่างไลฟ์และหลังหยุด — ไม่ถูกล้างโดยการขึ้นไลฟ์
  • ข้อความคำเตือนตรงกับ i18n เดิม ไม่เพี้ยน/ไม่หาย
  • รีเฟรชแล้วสถานะเดิมกลับมา ไม่ใช่ผ้าใบเปล่า

▸TC-RER-02 คุณภาพภาพฝั่งผู้ชมในโหมดส่งตรง — ไม่กระตุก ปาก-เสียงตรง (regression TAKRA-952) Boundary/Edge UI P0 รอเทส
คุณภาพภาพฝั่งผู้ชมในโหมดส่งตรง — ไม่กระตุก ปาก-เสียงตรง (regression TAKRA-952)
Priority: P0 · UI · ประเภท: Boundary/Edge (เกณฑ์ตัวเลข · ไลฟ์ยาว · จุดข้ามเพดาน 20 นาที) · 🧹 Round 1 — เคลียร์ของค้างที่บล็อกความเชื่อมั่น

Test Steps

  1. เปิดเว็บ TAKRA AI แล้วเข้าสู่ระบบด้วยบัญชี UAT → ที่หน้าหลักกด "เปิดห้องไลฟ์" ของห้องที่จะใช้ทดสอบ
  2. เริ่มไลฟ์โหมดส่งตรงจากเครื่องสเปกเดียวกับที่เคยเจอปัญหา (จดสเปก + ความเร็วเน็ตขาขึ้น)
  3. เปิดไลฟ์ดูจากมือถือเครื่องที่สอง ในฐานะผู้ชม (ไม่ใช่จอ operator)
  4. อัดคลิปหน้าจอฝั่งผู้ชม ต่อเนื่อง ≥ 3 นาที ในนาทีที่ 1, 20 และ 45 ของไลฟ์
  5. ระหว่างอัด สังเกต: ภาพกระตุก/เฟรมตก · เสียงขาด · ปากไม่ตรงเสียง
  6. จดค่า bitrate ที่แผงควบคุมโหมดส่งตรงแสดง ณ เวลาที่อัดแต่ละครั้ง

Expected Result

  • คลิปฝั่งผู้ชมดูลื่นต่อเนื่อง ไม่มีอาการเฟรมตกหนักแบบที่เคยเจอ (~10fps)
  • ปากอวตารตรงกับเสียง ไม่มีเสียงขาดเป็นช่วง
  • คุณภาพนาทีที่ 45 ไม่แย่ลงกว่านาทีที่ 1 (ไม่ใช่ดีตอนต้นแล้วทรุด)
  • bitrate ที่แผงแสดงสอดคล้องกับสิ่งที่เห็นจริง ไม่ใช่ตัวเลขนิ่งขณะภาพค้าง

เนื้อหาหมุนไม่ซ้ำในหน้าต่าง 8 นาที + ลูป 2 ขึ้นไปสลับลำดับ (ปิดของค้าง TAKRA-103)
Priority: P0 · UI · ประเภท: Data (ตัวเลขบนจอ/สรุปหลังไลฟ์ ตรงกับสิ่งที่เกิดจริง) · 🧹 Round 1 — เคลียร์ของค้างที่บล็อกความเชื่อมั่น

Test Steps

  1. เปิดเว็บ TAKRA AI แล้วเข้าสู่ระบบด้วยบัญชี UAT → ที่หน้าหลักกด "เปิดห้องไลฟ์" ของห้องที่จะใช้ทดสอบ
  2. เตรียมร่างไลฟ์ที่มีอย่างน้อย 2 slot ที่มี content ≥ 2 ชิ้น และข้อความต่างกันชัดจนแยกออกด้วยหู
  3. ตั้งฉากให้ 1 ลูปสั้น (~2–3 นาที) เพื่อให้วนหลายรอบเร็ว

  5. ถอดลำดับที่ได้ยินจริงออกมาเป็นตาราง: เวลา → slot → content ที่พูด
  6. เทียบลำดับ slot ของลูปที่ 1 กับลูปที่ 2, 3

Expected Result

  • ไม่มี content ชิ้นเดิมถูกพูดซ้ำภายใน 8 นาที ตราบใดที่ slot นั้นยังมีตัวเลือกอื่นเหลือ
  • ลูปที่ 1 เรียงตามลำดับที่จัดไว้ใน Scene Builder (hook มาก่อน pitch)
  • ลูปที่ 2 ขึ้นไปสลับลำดับ และลำดับไม่เปลี่ยนกลางลูป
  • ทุก slot ในฉากถูกเล่นครบทุกลูป ลูปละครั้ง — ไม่มี slot ไหนหายหรือซ้ำในลูปเดียว
ปิดเกณฑ์ Q3 เนื้อหาไม่ซ้ำ — เกณฑ์ปิด: ไม่มี content ซ้ำภายในหน้าต่าง 8 นาที · ลูป 2+ สลับลำดับจริงและเสถียรทั้งลูป · ประเภท: Manual · ที่มา: takra-ai-rerun-quality-plan.html (QA · 2026-09-09) · ฐานโค้ด develop @ f842a7f2

"หยุดไลฟ์" กับ "ปิดไลฟ์" ผู้ใช้ต้องแยกออกจากหน้าจอ (TAKRA-961)
Priority: P0 · UI · ประเภท: Validation (กฎ/ข้อความบนหน้าจอถูกต้องตามที่ออกแบบ) · 🧹 Round 1 — เคลียร์ของค้างที่บล็อกความเชื่อมั่น

Test Steps

  1. เปิดเว็บ TAKRA AI แล้วเข้าสู่ระบบด้วยบัญชี UAT → ที่หน้าหลักกด "เปิดห้องไลฟ์" ของห้องที่จะใช้ทดสอบ
  2. ขึ้นไลฟ์โหมดส่งตรงจนเห็นภาพบน TikTok
  3. กด "หยุดไลฟ์" แล้วดู: ห้อง TikTok ปิดไหม · สถานะรอบบนหน้า My Lives / คอนโซล เป็นอะไร

  • หน้าจอบอกชัดว่า "หยุดไลฟ์" = ปิดเฉพาะห้อง TikTok แต่รอบยังเดิน — ผู้ใช้ไม่ต้องเดา

  • ไม่มีสถานะกำกวมค้างบน My Lives (เช่น ยัง "กำลังไลฟ์" ทั้งที่ TikTok ปิดไปแล้ว)
